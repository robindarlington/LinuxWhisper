Create src/linuxwhisper/config/validation.py:
- Import `logging`, `subprocess`, `json`, `os`, `shutil` from stdlib. Import `ecodes` from `evdev`.
- `def validate_hotkey(hotkey_str: str) -> tuple[bool, int | None, str]`:
  Validate a hotkey configuration string and return its evdev key code.
  Normalize: if not starting with "KEY_", prepend "KEY_" and uppercase. Use `getattr(ecodes, key_name, None)`. If None, build a list of available function keys (`KEY_F1` through `KEY_F24` that exist on ecodes) and return `(False, None, f"Unknown hotkey: '{hotkey_str}'. Available function keys: {available}")`. Otherwise return `(True, key_code, "")`.

- `def check_compositor_conflicts(hotkey_str: str) -> list[str]`:
  Check if the configured hotkey conflicts with compositor key bindings. Returns a list of conflict description strings (empty if no conflicts).
  1. Try Hyprland first: check if `shutil.which("hyprctl")` exists. If so, run `subprocess.run(["hyprctl", "binds", "-j"], capture_output=True, text=True, timeout=2)`. If returncode 0, parse JSON output. For each binding, check if `hotkey_str.upper()` matches the binding's `"key"` field (case-insensitive). Append `f"Hyprland: {bind.get('key', '')} bound to {bind.get('dispatcher', 'unknown')}"` for each conflict.
  2. Try Sway: check if `shutil.which("swaymsg")` exists. If so, run `subprocess.run(["swaymsg", "-t", "get_binding_modes"], capture_output=True, text=True, timeout=2)`. Note: Sway doesn't expose individual bindings via IPC in the same way, so just log a debug message that Sway binding validation is limited. Skip detailed checking for Sway (research confirms no reliable programmatic query for individual bindings).
  3. For other compositors (KDE, GNOME), log debug message that compositor binding validation is not available. Return empty list.
  4. Wrap everything in try/except to handle missing tools, timeouts, JSON parse errors. Never fail -- always return a list (possibly empty). Log errors at debug level.

- `def validate_config_input(config: dict) -> list[str]`:
  Validate the input-related configuration fields. Returns a list of error strings (empty if valid).
  1. Validate hotkey: call `validate_hotkey(config.get("hotkey", "F13"))`. If invalid, append the error message.
  2. Validate mode: check `config.get("mode", "hold")` is one of "hold", "toggle". If not, append `f"Invalid mode: '{mode}'. Valid modes: hold, toggle"`.
  3. Return error list.

All functions should use `logger = logging.getLogger(__name__)`.

- Add import: `from linuxwhisper.input.modes import InputMode, get_mode_from_config`
- Add import: `from linuxwhisper.config.validation import validate_hotkey, check_compositor_conflicts, validate_config_input`

In `DictationPipeline.__init__`:
- Add: `self._mode = get_mode_from_config(config)`. Log `f"Input mode: {self._mode.value}"`.
- Add: Validate hotkey config at init: call `validate_config_input(config)`. If errors, raise `ValueError(f"Invalid configuration: {'; '.join(errors)}")`.
- Add: Check compositor conflicts: call `check_compositor_conflicts(config.get("hotkey", "F13"))`. For each conflict, log a warning: `f"Hotkey conflict detected: {conflict}"`.

Replace the existing `_on_hotkey_press` and `_on_hotkey_release` methods with mode-dependent dispatch:

- `_on_hotkey_press(self) -> None`:
  If `self._mode == InputMode.HOLD`:
    - Same as current: if state is IDLE, transition to RECORDING, start recording.
  If `self._mode == InputMode.TOGGLE`:
    - If state is IDLE: transition to RECORDING, start recording. Log "Toggle: recording started".
    - If state is RECORDING: transition to PROCESSING, run the processing flow (stop recording, transcribe, inject). This is the "stop" press in toggle mode. Log "Toggle: recording stopped".
    - If state is PROCESSING or INJECTING: ignore the press (user pressed while still processing previous recording). Log debug "Toggle press ignored: pipeline busy ({state})".

- `_on_hotkey_release(self) -> None`:
  If `self._mode == InputMode.HOLD`:
    - Same as current: if state is RECORDING, transition to PROCESSING, run processing flow.
  If `self._mode == InputMode.TOGGLE`:
    - Do nothing (release is irrelevant in toggle mode). No log needed.

Refactor: Extract the "stop recording + transcribe + inject" logic from the current `_on_hotkey_release` into a private method `_process_recording(self) -> None` that both hold-release and toggle-stop can call. This method:
  1. Calls `self._recorder.stop()` to get audio_data
  2. Checks minimum duration (< 0.1 seconds worth of samples)
  3. Saves WAV to temp file
  4. Calls `self._engine.transcribe(wav_path)`
  5. Cleans up temp WAV
  6. If text is non-empty, transitions to INJECTING and calls `self._injector.type_text(text)`
  7. Transitions to IDLE
  8. All wrapped in try/except that transitions to IDLE on error

Add a property:
- `@property mode(self) -> InputMode`: Return `self._mode`.

Add a method for config updates (used by Plan 02 for reload):
- `def update_config(self, new_config: dict) -> None`: Update mode via `self._mode = get_mode_from_config(new_config)`. Update hotkey: if hotkey changed, store new hotkey name for reference (actual detector restart is handled at daemon level). Log "Pipeline config updated: mode={self._mode.value}".
